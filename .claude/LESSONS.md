# Lessons

- usage-tracker: bb reports no window start. Derive elapsed time from `resetsAt` and a fixed duration (5h / 7d). Model-scoped windows (Fable) share the weekly reset time, so 7d is correct.
- Verify plugin math against live data: `curl -X POST http://127.0.0.1:<port>/api/v1/plugins/usage-tracker/rpc/getUsage -d '{"threadId":null}'`. The port is in `~/.bb/bb-app-runtime.json`.
- `bb plugin list` keeps the install-time version after `bb plugin reload`; the reloaded code is still current.
- The Bash tool keeps its cwd between calls. Do not `cd` a relative path a second time; the chain fails.
- iOS 26 Safari ignores `theme-color`. It samples a fixed/sticky top element (top ≤4px, height >10px, width ≥90%, opaque bg, z-index ≥0). No candidate → black canvas in a tab, gradient bar in a Home Screen app. Give it a fixed rail (`ios-status-bar` plugin).
- `apple-mobile-web-app-status-bar-style` is read at Add-to-Home-Screen time. A runtime change needs a reinstall. Prefer CSS fixes.
- Content scripts cannot read plugin settings; only React slots have `useSettings`. Keep content-script plugins setting-free or add a settings slot.
- The fixed rail fixes the Safari tab but not the iOS 26 Home Screen app: WebKit still draws the scroll-pocket blur under `black-translucent`. iOS takes `apple-mobile-web-app-status-bar-style` from the served HTML at Add-to-Home-Screen time; a runtime DOM change is ignored even after a remove + re-add. Only a bb `index.html` change (`default`, as X uses) fixes standalone.
- zsh `noclobber` is on in the Bash tool: use `>|` to overwrite an existing file.
- `cp` is interactive in the Bash tool too: overwriting a file prompts and then silently does nothing. Restore a backup with `cat backup >| target`.
- WebKit edge tint = hit test at one point per edge (center x, 4px in); topmost painted fixed/sticky element wins; colors are collected from the whole ancestor chain (a `::before` tint still counts). Win with a fixed rail at max z-index, height >= 16px, opaque `background-color`, no `backdrop-filter`. Do rails for top and bottom.
- bb zen mode (`Make prompt box larger`) is hidden on thread composers ≤767px: `FollowUpPromptBox` passes `compact` and `enterZenMode` bails on it. No SDK API toggles it. Emulate with `app.composer.customize({ actions })` + CSS on `[data-promptbox-editor-scroll]` (inline styles → `!important`).
- Headless Chromium (playwright-core from the vaam monorepo + `~/Library/Caches/ms-playwright`) cannot launch inside the sandbox (Mach port bootstrap denied). Run the check script with the sandbox off against `serverUrl` in `~/.bb/bb-app-runtime.json`; thread URL is `/projects/<proj>/threads/<thr>`.
- `PluginSidebarThread` has no queued-message field. Read the queue server-side with `bb.sdk.threads.queuedMessages.list({ threadId })`, cache per thread, and refresh on `bb.sdk.subscribe({ event: "thread:changed" })` when `changes` includes `"queue-changed"`. Push to the app over `bb.realtime.publish`.
- App-side hooks must import only types from `server.ts`. A runtime import pulls zod into `dist/app.js`. Put shared constants (setting keys, channel names) in `inbox.ts`.
- The testing harness rejects an RPC method with no handler. Any hook that calls a new RPC must `.catch` or every old test gets an unhandled rejection.
- Live smoke test for the t3sidebar backend: `curl -X POST http://127.0.0.1:<port>/api/v1/plugins/t3sidebar/rpc/<method> -H 'content-type: application/json' -H 'Origin: http://127.0.0.1:<port>'`. `bb thread queue create|delete <threadId>` drives the queue.
- A bb update can leave a path-installed plugin with a stale frontend bundle that crashes on load while `bb plugin list` says `running`. Fix: `bb plugin remove <id>` then `bb plugin install <path> --yes`; bb rebuilds `dist/app.js` against the running SDK. `remove` wipes the plugin's settings but keeps its SQLite data. Reproduce frontend crashes headless with `/tmp/t3check/check.mjs`-style playwright-core (vaam-main node_modules), sandbox off, on `serverUrl` from `~/.bb/bb-app-runtime.json`; the remote getbb.app URL needs a sign-in.
- t3sidebar headless checks: a row on a collapsed shelf (Working/Snoozed/Settled) is not in the DOM. Click `section[aria-label="Working"] button[aria-expanded]` first, then query `[data-sidebar-thread-id]`.
